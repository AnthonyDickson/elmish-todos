# Elmish Todos

A port of [TodoMVC in Elm](https://github.com/evancz/elm-todomvc/) (which is based on
[TodoMVC](https://github.com/tastejs/todomvc)) in F# using Elmish and Feliz.

## Getting Started

All commands run from the repo root.

```bash
# Build the server (auto-applies DB migrations at startup)
make server-build

# Run the server
make server-run

# Format code (fantomas)
make format

# Lint
make lint

# Start the client dev server
make client-watch

# Build the client dist bundle
make client-build

# Single-file publish (builds client, copies assets, publishes server)
make publish
```

### Database (SQLite)

The app persists todos to a local SQLite database (`todos.db`). Schema changes are managed with [DbUp](https://github.com/DbUp/DbUp) migrations and type-safe queries via [SqlHydra](https://github.com/JordanMarr/SqlHydra).

**First run** — just build and run. DbUp creates the database and applies migrations at startup. `Db.fs` (generated types) is committed to source control, so no code-gen step is needed.

```bash
make server-build
make server-run      # creates todos.db + applies all migrations
```

**Changing the schema** — add a migration, apply it, regenerate types, fix compile errors.

```bash
make db-migration name=add_priority   # scaffolds migrations/002_add_priority.sql
# … write the SQL (CREATE TABLE, ALTER TABLE, etc.) …
make db-update                        # applies migrations + regenerates Db.fs
# … fix any compile errors in Todos.fs (mapping layer between DB types and API types) …
make server-build
```

**Starting fresh** — blow away the database and re-apply everything.

```bash
make db-reset                         # deletes todos.db, re-applies migrations, regenerates types
```

**Available targets:**

| Target                          | What it does                                                                |
| ------------------------------- | --------------------------------------------------------------------------- |
| `make db-migration name=<name>` | Scaffolds a sequentially-numbered migration file in `migrations/`           |
| `make db-migrate`               | Applies pending migrations via standalone script (no build required)         |
| `make db-generate`              | Runs `dotnet sqlhydra sqlite` to regenerate `Db.fs` from the live DB        |
| `make db-update`                | `db-migrate` + `db-generate` — full schema update in one command            |
| `make db-reset`                 | Deletes `todos.db`, re-applies all migrations, regenerates types            |

**How it works:**

- **`migrations/*.sql`** — Numbered SQL files embedded in the assembly. DbUp applies them in order, tracking which have run in a `SchemaVersions` table. Never modify an already-applied migration — add a new file instead.
- **`Db.fs`** — Auto-generated by SqlHydra from the live database schema. Contains record types (`main.todos`), table declarations, and a `QueryContextFactory`. Committed to source control so the project compiles immediately after clone.
- **Mapping layer** — `Todos.fs` converts between DB row types and the public API `Todo` type (e.g. `int64` ↔ `bool` for `Completed`, `string` ↔ `DateTime` for `CreatedAt`). This is the control point — DB columns never leak to the API.
- **Connection string** — `Data Source=todos.db` in `appsettings.Development.json` (relative, resolves to repo root). Override with `ConnectionStrings__Default` env var in production (use an absolute path like `/data/todos.db`).
```

### Publishing

```bash
make publish                    # linux-x64 (default)
make publish RUNTIME=osx-arm64  # macOS Apple Silicon
```

Builds the client, copies it into the server's `wwwroot/`, then publishes the server as a self-contained single-file binary with trimming. Output at `src/ElmishTodos.Server/bin/Release/net10.0/<runtime>/publish/`.

### Static Assets

**Client assets** (images, fonts, favicons, PDFs — anything the SPA references) live in `src/ElmishTodos.Client/public/`. Vite serves them at root in dev and copies them into `dist/` on build.

**Server-only assets** (e.g. `robots.txt`) live in `src/ElmishTodos.Server/wwwroot/`. The `wwwroot/` directory is gitignored and populated by `make copy-client-dist` during publish — persistent server assets should have their source of truth elsewhere (e.g. a build step).

### Authelia (Dev-only OIDC Provider)

> [!WARNING]
> Development only — Authelia, its secrets, and certs are local dev fixtures.
> For production, see [Production OIDC Setup](docs/prod-oidc-setup.md).

```bash
docker compose up -d   # start Authelia at https://127.0.0.1:9091 (self-signed cert)
docker compose down    # stop
```

**Test user:** `dev` / `dev-password`

Auth endpoints on the .NET server (port 5000):

| Endpoint           | Purpose                         |
| ------------------ | ------------------------------- |
| `GET /login`       | OIDC challenge → Authelia login |
| `GET /logout`      | Sign out of cookie session      |
| `GET /signin-oidc` | OIDC callback                   |

Protected endpoints return `401`; the SPA redirects to `/login` on receipt.

### Development Environment

The project uses a Nix flake providing `.NET SDK 10`, `fsautocomplete` (LSP), and `dprint` (markdown formatting):

```bash
nix develop   # or direnv allow if direnv is configured
```

Local .NET tools (fantomas, fsharplint, fable) are defined in `.config/dotnet-tools.json`. The flake's `shellHook` runs `dotnet tool restore` automatically.

### Adding Dependencies

This project uses NuGet's [Central Package Management](https://learn.microsoft.com/en-us/nuget/consume-packages/central-package-management) (CPM).
All package versions live in `Directory.Packages.props` — project files reference them by name only, with no version attribute.

```xml
<!-- Directory.Packages.props — single source of truth -->
<Project>
  <ItemGroup>
    <PackageVersion Include="Oxpecker" Version="2.0.0" />
    <PackageVersion Include="Fable.Core" Version="5.0.0" />
    <!-- … -->
  </ItemGroup>
</Project>
```

```xml
<!-- In .fsproj files — name only, version comes from Directory.Packages.props -->
<PackageReference Include="Oxpecker" />
```

**To add a new dependency:**

```bash
# dotnet add package handles CPM — it adds the PackageReference
# to the .fsproj and the PackageVersion to Directory.Packages.props
dotnet add src/ElmishTodos.Server/ElmishTodos.Server.fsproj package SomePackage
```

The CLI writes the version into `Directory.Packages.props` and a bare `<PackageReference>` into the `.fsproj`.
To upgrade a version, edit `Directory.Packages.props` directly and run `dotnet restore --force-evaluate --project <project>`.

The shared project (`src/ElmishTodos.Shared/`) contains types used by both client and server.
It uses conditional `PackageReference` with `FABLE_COMPILER` to select `Thoth.Json` (client) or `Thoth.Json.Net` (server) — both versions are defined in `Directory.Packages.props`.
